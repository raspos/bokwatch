## 2. 기존 예측 엔진

### 2-1. 합성 KOFR OIS (`bokwatch/kofr_ois.py`)
- 산식: 합성 OIS(T) = CD(T) − 스프레드(T). CD는 금투협 CD 시가평가(7일·15일·1개월)와 CD 91일(ECOS).
- 스프레드(T) = 과거 각 날짜의 "CD(T) − 그 뒤 T일 실제 KOFR 일복리"의 중앙값(최대 5년, 기간이 끝난 관측만, 최소 60개).
- KOFR 공시가 2021-11-25부터이고 금투협 CD 곡선 저장이 2023-01-09부터라, OIS 계열 모형은 2023-02 회의부터 평가 가능하다.
- 실제 거래된 OIS가 아니다. 예탁원 'KOFR OIS 추정금리'는 2025-10-24 이후 공시가 없고 재배포가 금지돼 있다.
- 회의 역산: 1개월물로 다음 회의(회의 뒤 15일 이상일 때), 3개월물로 그다음 회의. 2026-11-11부터는 뒤 회의의 오차 확대가 2배를 넘으면 확률 대신 "참고 추정"으로 낸다.

### 2-2. 통안채 91일 (`awm_data.single_model`)
- 정상 스프레드: 기준금리가 직전 120일 바뀌지 않은 날의 (금리 − 기준금리) 중앙값, 직전 730일, 20개 이상 관측(`market.pit_spread`). 11/23 기준 −0.95bp.
- 만기 91일 안에 들어간 모든 회의를 한 식으로 푼다(`model.solve`, method=auto). 한 구간에 새 회의가 둘 이상이면 "최소 인상 경로"로 둔다.
- 화면 입력표가 보이던 −3.5bp는 설정의 고정 동결 구간(2023-02-24~2024-08-21)으로 만든 값이었다. 2026-11-25에 종합 예측과 같은 값으로 표시를 맞췄다.

### 2-3. 50:50 종합 (`awm.Fixed("ois", "msb91", 0.5)`)
- 세 범주(인상·동결·인하) 확률을 단순 평균한다. 가중치를 학습하지 않는다.
- 두 입력 중 하나라도 없으면 종합 예측을 만들지 않는다.

### 2-4. 확률 변환·상하한 (`model.move_distribution`, `awm.clip_norm`)
- 기대 금리 변화 Δ를 25bp 격자에서 선형으로 나눈다. Δ=+10bp면 25bp 인상 40%, 동결 60%.
- 25bp를 넘는 Δ는 25bp 확정 + 초과분을 50bp 확률로 둔다.
- 확률 하한 1e-6, 합계 1로 정규화. 확률 축소(shrinkage)나 교정(calibration)은 없다. 그래서 틀리면 로그손실이 크다(항상 동결 2.76).

### 2-5. AWM 구조
- 칸 = (금통위, 관측 시점 D∈{30,20,10,5,3,1}영업일 전). 모형 14종, 금통위 순서 확장 창 워크포워드, 앞 6회는 학습 전용.
- 칸이 회의당 6개라 독립 표본이 아니다. 신뢰구간은 금통위 단위 군집 부트스트랩이다.

## 3. 기존 백테스트 감사

| 점검 | 확인 결과 |
|---|---|
| 표본 | 정식 30개 회의(2023-02-23~2026-10-22): 인상 2·동결 24·인하 4. 긴 표본 40개(2021-11-25~)는 통안채·CD만 가능하고 인상 11 |
| 학습·평가 분리 | 모형 학습은 이전 회의만 쓴다(워크포워드). 후보 모형·burn-in·구간 선택은 자료를 본 뒤 했다(`kind.post_hoc`) |
| 같은 표본으로 선택·평가 | 50:50은 학습이 없어 과적합은 없지만, 후보 목록에서 고른 것 자체가 사후 선택이다 |
| 동결기 편중 | 동결 80%. 항상 동결 Brier 0.40, Brier 비교가 동결 편중에 영향받는다 |
| 회의별 가중 | 회의당 6칸 균등. 회의 단위로 군집 처리한다 |
| 국면별·시계별 | `by_regime`·`by_volatility`·`brier_by_horizon`이 있으나 "탐색적"이라고 표시돼 있다. 인상 회의는 2회라 통계적 힘이 약하다 |
| 사후 수정 자료 | KOFR 후공시와 CD 곡선 수정으로 같은 날 값이 달라진다(`stored` vs `retro`). 이번 11/26 아침 저장 값과 재계산 값의 차이 확인 |
| 당시 이용 불가 자료 | OIS 스프레드는 기간이 끝난 관측만 쓰도록 짰다. 통안채 스프레드는 당시까지 자료만 쓴다. 이 부분은 단위 테스트로 보호돼 있다(`test_no_future_information_in_training`) |

### 3-1. 재현
- 방법: `bokwatch.awm_live.write_backtest`를 별도 경로로 실행(`engine3/repro_awm_backtest.json`).
- 결과: 공개 표와 같은 순서·비슷한 값. M0 0.4516, M2 0.5332, M3 0.2825, M5 0.3000, M6c 0.3020, M7 0.3248. 공개 값(10/29)과 달라진 것은 표본이 31개 회의로 늘었기 때문이다.

### 3-2. 공개 표(30개 회의) 상위권

| 모형 | Brier | 로그손실 |
|---|---|---|
| M3 통안채 91일 단독 | 0.2847 | 0.60 |
| M5 OIS+통안채 50:50 | 0.3024 | 0.49 |
| M6c 기간 연속형 가중치 | 0.3045 | 0.49 |
| M7 최근 오차 반영 | 0.3281 | 0.52 |
| M0 항상 동결 | 0.4000 | 2.76 |
| M2 합성 OIS 단독 | 0.5420 | 1.69 |

### 3-3. burn-in 민감도
- burn-in 6회(30개 회의): M3 0.2847 < M5 0.3024.
- burn-in 3회(33개 회의, 인상 5): M5 0.2901 < M3 0.3193.
- 같은 모형이 표본 선택에 따라 순위가 바뀐다. 3.0의 최종 평가는 이런 사후 선택을 하지 않는 구조로 새로 짠다.
